### Клиентская оптимизация
1.  Скорость получения контента.</br>
Позволяет без особых затрат процессора, с минимальным копированием оперативной памяти отдавать файлы с диска клиенту.</br>
Работает только с http.</br>
В данной конфигурации используется так как дает прирост производительности и сайт в настоящее время работает по http. </br>
   **sendfile on;**</br>
2. Сокращение трафика. Данные отправляются в одну сессию.</br>
Группировка данных в большие пакеты (работает только с sendfile)</br>
   **tcp_nopush on;**</br>
3. Снижение задержки.</br>
Немедленная отправка данных</br>
   **tcp_nodelay on;**</br>
4. Сокращение трафика.</br>
Настройки keep-alive соединений. Позволяет некоторое время держать сессии открытыми,</br>
без необходимости повторных handhake при установлении TCP сессии.</br>
  - Таймаут ожидания новых запросов по тому же TCP-соединению</br>
      **keepalive_timeout 120;**</br>
  - Максимум HTTP-запросов по одному TCP-соединению. Клиент сразу получит весть запрашиваемы контент</br>
      **keepalive_requests 1000;**</br>
5. Оптимизация кэширования.</br>
 Единожды загрузив какой-то ресурс он перестает повторно загружаться, повторно не отправляется запрос за ним.</br>
  - Максимальное количество открытых дескрипторов файлов в течении 60 секунд</br>
      **open_file_cache max=10000 inactive=60s;**</br>
  - Проверка актуальности кэша каждые 30s. Для отдачи актуального контента.</br>
      **open_file_cache_valid 30s;**</br>
  - Файл помещается в кэш при обращении к нему 2 раза</br>
      **open_file_cache_min_uses 2;**</br>
  - Не кэшировать ошибки</br>
      **open_file_cache_errors off;**</br>
6. Сокращение трафика. Сжатие</br>
Для наглядности сжатие текста настроено только для одной страницы "Бухта Витязь"</br>
``` #Сжатие текста для этого location
     gzip on;
     gzip_static on;
     gzip_types text/plain text/css text/xml application/javascript application/json application/font image/svg+xml;
     gzip_comp_level 3;
     gzip_proxied any;
     gzip_min_length 1000;
     gzip_vary on;
```

### Настройка серверного кэширования для одной страницы ( ![default.conf](./default.conf) )
кэширование результат работы backend (WordPress) для исключения повторного обращения к нему angie
В конфиге ![angie.conf](./angie.conf) включается кэширование, описывается зона "one"
``` #Серверное кэширование http
    fastcgi_cache_valid 1m;
    fastcgi_cache_key $scheme$request_uri;
    fastcgi_cache_path /cache levels=1:2 keys_zone=one:10m:file=/etc/angie/cache.state inactive=24h max_size=800m;
```
/cache — директория для кэша
levels=1:2 — структура поддиректорий
keys_zone=one:10m — 10 МБ shared memory для ключей кэша
file=/etc/angie/cache.state — состояние кэша между перезапусками
inactive=24h — удалять неактивные записи через 24 часа
max_size=800m — максимум 800 МБ на диске для кэша

В конфиге ![default.conf](./default.conf) для директори одной страницы "Бухта Витязь"
подключается и настраивается зона кэширования "one".
```  fastcgi_cache one;                                             # использовать зону "one"
     fastcgi_cache_valid 200 10m;                                   # кэшировать на 10 минут при доступе контента
     fastcgi_cache_lock on;                                         # Обновление кэш только один раз
     fastcgi_cache_min_uses 2;                                      # Кэширование только при повторном обращении
     fastcgi_ignore_headers "Cache-Control" "Expires" "Set-Cookie"; #Кэширование не смотря на запрещающие заголовки от бэкенда
     fastcgi_cache_background_update on;                            # Разрешение на отдачу устаревшего кэша
   #Проверка работы серверного кэширования
     add_header X-cache-status $upstream_cache_status;
     add_header X-cache-key $scheme$host$uri;
```
